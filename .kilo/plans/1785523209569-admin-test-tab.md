### Test Result Types

```typescript
type TestStatus = 'idle' | 'running' | 'passed' | 'failed' | 'skipped';

interface TestResult {
  id: string;
  name: string;
  category: string;
  status: TestStatus;
  duration: number | null;
  error: TestError | null;
  timestamp: number | null;
}

interface TestError {
  message: string;
  statusCode: number | null;
  responseBody: string | null;
  requestDetails: {
    url: string;
    method: string;
    body: string;
  };
  possibleCauses: string[];
}
```

### Debug Section (shown when test fails)

For each failed test, expand a debug panel below the test row showing:

1. **Status Code** — highlighted in red (e.g., `401 Unauthorized`, `429 Too Many Requests`, `500 Internal Server Error`, `Network Error`, `Timeout`)
2. **Error Message** — the raw error string
3. **Possible Causes** — context-aware suggestions based on status code:
   - `401`: "API key is missing, invalid, or expired. Check Admin > API Keys tab."
   - `403`: "Access forbidden. Key may lack required permissions."
   - `429`: "Rate limit exceeded. Wait before retrying."
   - `500/502/503`: "Server error. The upstream API may be experiencing issues."
   - `Network Error`: "Cannot reach the API. Check internet connection or CORS policy."
   - `Timeout`: "Request timed out. The API may be slow or unreachable."
   - Missing key: "No API key found. Add it in Admin > API Keys tab."
4. **Request Details** — collapsible section showing URL, method, and request body (JSON pretty-printed)
5. **Response Body** — collapsible section showing raw response text (JSON pretty-printed if possible)

### "Run All Tests" Behavior

- Sequentially runs all non-skipped tests (to avoid rate limits)
- Updates each row in real-time as results come in
- Shows a summary banner at the top: `● X passed  ✗ Y failed  ○ Z skipped`
- Tests that require keys not present in localStorage are auto-skipped with reason "No API key configured"
- Long-running tests (generate-article, bynara-proxy, generate-image) are skipped in "Run All" but can be individually triggered

### Implementation Details

- Use `useState` for test results array and `useRef` for abort controller
- Each test wrapped in try/catch with `performance.now()` for timing
- For Supabase Edge Functions: use `supabase.functions.invoke()` and check both `error` and `data` for error responses
- For direct API calls: use `fetch()` with timeout via `AbortSignal.timeout(15000)`
- Import existing service functions where possible (e.g., `getGeminiApiKey`, `getTavilyApiKey`) to check key presence
- Match existing CSS patterns: `bg-white border border-slate-200 rounded-lg`, `text-slate-600`, `bg-green-50 text-green-700`, `bg-red-50 text-red-700`
- Use lucide-react icons: `FlaskConical`, `Check`, `X`, `Clock`, `SkipForward`, `ChevronDown`, `ChevronRight`, `AlertTriangle`, `Play`, `Loader2`

### Key Presence Check Logic

Before each test, check if required localStorage key exists:
```typescript
const hasKey = (key: string) => !!localStorage.getItem(key)?.trim();
```
If no key → status `'skipped'`, error message: `"No API key configured — add it in Admin > API Keys"`.
